# Issue 005 — Glossary and Critique Schema

## Purpose

Create the foundational machine-operational layer for the painting critique knowledge base.

This issue introduces:

1. glossary.md
2. critique_schema.md

These documents will:
- stabilize terminology,
- support future retrieval systems,
- improve prompt consistency,
- and prepare the project for structured AI-assisted critique workflows.

---

# Part 1 — glossary.md

## Goal

Create a canonical glossary of recurring project terminology.

The glossary should define:
- the preferred project meaning,
- related concepts,
- and usage boundaries.

---

## Candidate Terms

Include terms such as:

- value grouping
- focal hierarchy
- edge economy
- painterliness
- atmospheric simplification
- chroma hierarchy
- selective intervention
- repaint workflow
- tonal cohesion
- edge equality
- fragmentation
- shape economy
- shadow architecture
- dominant mass
- lost-and-found edge
- high-key structure
- visual noise
- edge clutter
- atmospheric greys

Add additional terms if clearly useful.

---

## Constraints

Definitions should:
- reflect project philosophy,
- remain concise,
- avoid academic jargon,
- and preserve painter-centered language.

---

# Part 2 — critique_schema.md

## Goal

Define a structured schema for future critique systems.

This is NOT implementation code.

This is a conceptual operational schema.

---

## Schema Requirements

The schema should support structured critique output such as:

- design
- value structure
- focal hierarchy
- edge economy
- chroma hierarchy
- atmosphere
- watercolor handling
- repaintability
- intervention priority

---

## Suggested Structure

Possible directions include:

- YAML-like structure
- JSON-like conceptual schema
- markdown structured schema

The focus is:
- clarity,
- extensibility,
- and future AI interoperability.

---

# Constraints

Do NOT:
- over-engineer,
- invent implementation details,
- or introduce unnecessary abstraction.

The schema should remain:
- human-readable,
- painter-centered,
- and pedagogically useful.

---

# Deliverables

Create:

- docs/knowledge-base/glossary.md
- docs/knowledge-base/critique_schema.md
